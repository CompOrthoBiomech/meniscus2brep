# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

The project is managed with uv and requires Python 3.13 or newer. Type checking uses basedpyright, a dev dependency configured under `[tool.basedpyright]` in `pyproject.toml`; keep it at 0 errors and 0 warnings. Ruff, also a dev dependency, formats code and sorts imports, configured under `[tool.ruff]` with a 150-character line length; run both commands below before committing.

```sh
uv sync                                        # install dependencies
uv run pytest                                  # run all tests
uv run pytest tests/test_vol.py                # run one test file
uv run pytest tests/test_vol.py::test_name     # run one test
uv run basedpyright                            # type check src and tests
uv run ruff check --fix                        # lint and sort imports
uv run ruff format                             # format code
uv add <package>                               # add a runtime dependency
uv add --dev <package>                         # add a dev dependency
uv build                                       # build sdist and wheel
uv run kneemesh-assemble --help                # single-label LabelMaps to a multilabel LabelMap
uv run kneemesh-brep --help                    # LabelMap to B-rep pipeline
uv run kneemesh-mesh --help                    # B-rep to mesh pipeline
uv run --group docs sphinx-build -W -b html docs docs/_build/html   # build the docs
```

`examples/` holds pipeline configurations for the real structures in `tests/dat`, run from the repository root, such as `uv run kneemesh-assemble --config examples/menisci_assemble.json`. The `knee_*` configurations handle all nine structures in one go: `knee_assemble.json` writes `examples/knee.nrrd`, `knee_brep_tet.json` or `knee_brep_hex.json` builds every structure from it, and `knee_mesh_tet4.json` or `knee_mesh_hex8.json` meshes them, the bones with tetrahedra either way. Brep examples that build bones cut 0.6 off their shafts (`bone.shaft_cut_fraction`), since the test data's shafts are long. Its `.gitignore` tracks only the configurations, so outputs and logs written there stay untracked.

## Docs

`docs/` is a Sphinx project with the Furo theme. Pages are Markdown through MyST, with `$...$` and `$$...$$` math rendered by MathJax. Napoleon reads the Google-style docstrings, and `autodoc_pydantic` renders config models with each field's type, default, `description`, and constraints, so document a config option in its `Field(description=...)`. The build treats warnings as errors.

## Type checking

basedpyright runs in `recommended` mode with these exceptions:

- SimpleITK, VTK, and gmsh ship without type information, so the rules about `Any` and unknown types and missing stubs are off. Annotate our own functions fully anyway.
- `reportUnusedCallResult` is off because gmsh and VTK calls return tags and status values that are often not needed.
- Under `tests/`, unannotated fixture parameters and private helper use are allowed.

Keep these points when writing code it checks:

- Pydantic coerces inputs such as `str` to `Path` or JSON text to a dict, but constructor signatures use the parsed types. Tests of coercion go through `Model.model_validate({...})`, and other code passes the parsed types.
- A fixture used only for its side effect, such as `in_tmp_path` changing directory, is requested with `@pytest.mark.usefixtures(...)` rather than an unused parameter.
- Narrow optionals before use, for example `assert saved is not None` in tests.
- A runtime check of a value its type already rules out, kept for untyped callers, takes `# pyright: ignore[reportUnreachable]` on the unreachable line.

## Architecture

The package converts segmented knee images into B-rep geometry and meshes, as a pipeline across `src/kneemesh/`. All nine structures are implemented: the menisci, the four cartilages (lateral and medial tibial, patellar, femoral), and the three bones. Root modules apply to every structure; the `geo/` and `mesh/` subpackages hold one module per structure or strategy (`meniscus.py`; `sheet.py` for every cartilage; `bone.py` for the three bones). `geo/femur.py` holds only the femoral cartilage's fit.

- `disk.py` reads and writes LabelMaps, `.vtp` poly data, and `.brep` files, and writes meshes in any volume format gmsh infers from the extension.
- `segmentation.py` defines `Segmentation`, a LabelMap with a `{name: value}` dict of its structures, and `assemble_label_maps`, which resamples named single-label LabelMaps onto one padded grid. `disk.write_segmentation` writes one as a LabelMap plus `<stem>_labels.json`, which `read_segmentation` reads back; the pipelines write it to `assembled_label_map` when that is set. Every B-rep pipeline reads a `Segmentation`, so cartilage can be oriented against its bone and anatomical neighbors can define surface and node sets.
- `vol.py` operates on LabelMaps: the signed distance field, isocontour extraction and smoothing, `require_3d_label_map`, and the `ContourSlice` value.
- `cartilage.py` holds what every cartilage shares: `classify_sides` splits a cartilage surface into its articular side and the side against its bone (`CartilageSides`), and `field_value` and `field_gradient` sample a distance field at physical points.
- `brep.py` holds the `BRep` value, `gmsh_session`, `export_brep`, the B-spline helpers that structure modules build geometry from (chord parameters, periodic and clamped fits, splitting, adding curves, wires, and swept surfaces to gmsh), the loop helpers that the meniscus's butterfly partition and the sheet's outlines use (`resample_closed`, `butterfly_split_indices`, `turning_angles`), and `contours_to_polydata`.
- `tet_meshing.py` meshes any solid B-rep with tetrahedra, with sizes defaulting to fractions of the shortest side of the B-rep's oriented bounding box (`oriented_extents`, principal axes of points sampled on its curves and non-planar faces): `min_size` 1/20, capped at `max_size`, so small features and curvature sizing cannot make excessively small elements, and `max_size` 1/4, at least `min_size`, because gmsh's own default from the overall extent left the thin real medial meniscus with no tetrahedra. It raises ValueError when gmsh produces no tetrahedra, and defines the `Mesh` it returns: node coordinates, per-type connectivity in gmsh's node ordering, gmsh element type numbers, and chains of nodes that optimization keeps straight (`straight_lines`, empty but for sheets' walls). Its `gmsh_options`, `import_solid`, `volume_mesh`, and `require_element_order` are shared with structure meshers. `write_mesh` rebuilds a `Mesh` as a discrete gmsh volume to write it.
- `mesh_optimization.py` moves the nodes of any hexahedral `Mesh` to raise its scaled Jacobians, and reports quality with `scaled_jacobians` and `mesh_quality`. Each mesh section's `optimize`, such as `--meniscus.optimize`, runs it after hexahedral meshing.
- `geo/meniscus.py` fits the centerline, slices the surface into ordered contours, lofts them into a B-rep with gmsh's Open Cascade kernel, and builds the five-block solid that hexahedral meshing needs.
- `mesh/meniscus.py` meshes the five-block solid into block-structured hexahedra.
- `geo/sheet.py` fits a cartilage sheet (`CartilageSheet`, heights of both sides over a domain within a perimeter) with `fit_sheet`, and builds its one solid for either element shape with `sheet_to_brep`: each side one B-spline surface whose parameters are the domain coordinates, trimmed by the perimeter and hole outlines, and straight walls ruled between the sides' rims. A `SheetFrame` maps domain points and heights to physical points: `PlaneFrame` (the default) or `CylinderFrame`.
- `mesh/sheet.py` meshes any sheet's solid with hexahedra (`hexahedral_mesh`): gmsh's quadrilaterals on one side, stacked along straight columns to the other side. `sheet_partition_brep` builds the blocks the quadrilaterals' irregular nodes divide the sheet into, one volume each.
- `geo/femur.py` fits the femoral cartilage over a cylinder (`fit_femoral_sheet`); its solid is `sheet_to_brep`'s.
- `geo/bone.py` makes a bone's closed, triangulated surface, not a B-rep: `bone_mask` fills cavities and cuts shafts the scan cuts off (`find_shaft_ends`) shorter, and `decimate_surface` reduces the smoothed isocontour's triangles. `mesh/bone.py` loads the surface into gmsh, which reparametrizes it, and meshes it with triangles or quadrilaterals (`surface_mesh`) or the solid with graded tetrahedra (`tetrahedral_mesh`). Bones are not meshed with hexahedra. `disk.read_surface` and `write_surface` handle the `.stl`; `write_mesh` writes surface meshes in a 2D entity.
- `config.py` provides `BaseConfig`, the pydantic base class for configuration models parsed from JSON, which rejects unknown keys. `Structure` is the `Literal` of the nine structure names (`lateral_meniscus`, `medial_meniscus`, `patellar_cartilage`, `femoral_cartilage`, `lateral_tibial_cartilage`, `medial_tibial_cartilage`, `femur`, `tibia`, `patella`), and the keys of every `labels`, `label_maps`, and `breps` mapping must be among them. `BONES` maps each cartilage to the bone that must share its segmentation. `LabelMapAssembly` configures `kneemesh-assemble`, `LabelMapBrep` `kneemesh-brep`, and `BrepMesh` `kneemesh-mesh`. The latter two hold the shared settings plus one section per kind of implemented structure, `meniscus: MeniscusBrep` / `MeniscusMesh` for both menisci and `cartilage: CartilageBrep` / `CartilageMesh` for the tibial and patellar cartilage, and `femoral_cartilage: FemoralCartilageBrep` / `FemoralCartilageMesh`, and `bone: BoneBrep` / `BoneMesh` for the three bones, which hold every pipeline argument with its default. B-rep sections extend `SurfaceBrep` (distance field and surface smoothing) and mesh sections but `BoneMesh` extend `StructureMesh` (tetrahedral sizing and hexahedral optimization). Bones (`BONE_STRUCTURES`) are written with `bone.output` (`.stl`) instead of `output`, and meshed with `bone.element_type` (`BoneElementType`, through `BONE_ELEMENT_TYPES`) instead of `element_type`, which also fills the mesh suffix's placeholder for them. `CartilageBrep` leaves `perimeter_radius` and `min_thickness` as None to pick defaults by `hex_blocks`, read through its `resolved_*` properties. Their `output` is a suffix: each structure is written to `output_directory / f"{structure}{output}"` by `output_path`. B-rep suffixes must end in `.brep`; the mesh suffix defaults to `_{element_type}.msh`, kept as a template so a changed `element_type` renames the output. `element_type` (`hex8`, `hex20`, `hex27`, `tet4`, `tet10`) replaces separate shape and order settings; `element_shape`, `element_order`, and `second_order_incomplete` are properties derived from it through `ELEMENT_TYPES`. Mapping fields accept JSON text, so they work as command-line options. The gmsh algorithm enums are string enums named for readability, with gmsh's option number on `.number` and case-insensitive lookup, so configs store them as plain names. Optional numbers read "none" as None.
- `pipeline.py` runs the three console scripts, none of which take a subcommand. `configure` takes one model, builds an option for every field and `--section.field` options in an argument group for every section, layers command-line values over `--config` (merging section options into the file's section field by field), and saves the result: `settings<timestamp>.json` in the working directory without `--config`, or `<stem>_modified.json` beside it when options change it. Command-line values arrive as strings and rely on pydantic's lax coercion. `load_segmentation` turns a config's `label_map` + `labels` or `label_maps` into a `Segmentation`; `run_assembly` and B-rep configs with `label_maps` share one assembly step. `run_brep` builds every structure in the segmentation, a cartilage's bone included, and `run_mesh` every structure in `breps`, each looking up the structure's name in `_BREP_BUILDERS` or `_MESHERS`, which cover every `Structure`. Builders return a `BRep`, or a bone's `vtkPolyData` surface; meshers take the file's path and read it themselves. Each output is written as soon as it is made.
- Logging uses loguru. `__init__.py` disables the `kneemesh` logger so the library stays silent; modules log step details at DEBUG. The pipelines enable it for the run, sending INFO to stderr and DEBUG to `assemble<timestamp>.log`, `brep<timestamp>.log`, or `mesh<timestamp>.log` in the working directory, or to `<config stem>.log` beside `--config`. They remove their handlers and disable the logger again on exit. Use `logger`, not `print`.

### LabelMap convention

A LabelMap is a scalar `sitk.Image` with pixel type `sitkUInt8`, `sitkUInt16`, or `sitkInt16` (`vol.LABEL_MAP_PIXEL_IDS`), not SimpleITK's run-length `sitkLabel*` pixel types. `disk.py` enforces this on both read and write and keeps the pixel type rather than casting. It accepts only `.nii`, `.nrrd`, and `.mhd` + `.raw`, so `.nii.gz` is rejected. `vol.signed_distance_field` and `geo.meniscus.centerline` additionally require a 3D image.

### Segmentations

A B-rep config gives either `label_map` with the required `labels` (`{structure: value}`) or `label_maps` (`{structure: path}`), never both. Every structure named is built, and a cartilage's bone (`BONES`) must be named too. `Segmentation` rejects value 0, duplicate values, and names whose value is absent from the image. Keep these points when changing `assemble_label_maps`:

- Every nonzero voxel of an input is its structure. Values are 1, 2, ... in input order, and a later structure overwrites earlier ones where they overlap, with a warning. A structure that vanishes in resampling or is entirely overwritten raises.
- The shared grid uses the first input's direction cosines. Each input axis counts toward the shared axis nearest it in direction, and each shared axis takes the smallest spacing from any input. Taking the minimum by index instead mixes up axes of inputs with permuted orientations.
- Along each axis the grid's voxel faces line up with the input that has the smallest spacing there, so that input resamples exactly when it shares the orientation. Anchoring to the bounding box's corner instead shifts it by up to half a voxel.
- `sitkLabelGaussian` is the default interpolator and `sitkNearestNeighbor` the alternative. Label Gaussian rounds thin corners even on an identical grid: it drops about 1% of the real test label.
- The default padding of 4 voxels keeps the distance field's Gaussian support inside the image around every structure.

### How `geo.meniscus.centerline` works

`sitk.BinaryThinning` only thins in 2D. Given a 3D image it thins slice by slice and returns a sheet, so it cannot produce the curve directly. It only provides the initial estimate:

1. Project the label along the image axis closest to its thinnest principal direction, then thin the 2D projection. The projection is padded with background first: thinning treats the image edge as an open end, so a label cut off by the edge would otherwise skeletonize into disconnected branches and the longest path would cover only part of the arc.
2. Take the longest path through the skeleton and trim one mean half-width from each end, because the skeleton forks into the label's corners there.
3. Fit a spline, then repeatedly replace it with a fit through centroids of cross-section slabs normal to the curve. Stations extend past both ends so the curve can grow back toward the tips, and partial sections at the tips are discarded.

Section spacing and smoothing tolerance scale with the structure's half-width as well as the voxel size. Tying them to the voxel size alone makes the curve hook at the tips on fine grids.

The result is a cubic `scipy.interpolate.BSpline` over u in [0, 1], in physical coordinates, and evaluating it at N parameters gives an `(N, 3)` array. `make_splprep` natively evaluates to `(3, N)`, so `_fit` rebuilds the spline to normalize this. Which end of the structure is u = 0 is unspecified, so compare curves by nearest-point distance rather than parameter by parameter.

### Cross-section contours

`signed_distance_field` feeds `extract_isocontour`, which returns a closed VTK triangle mesh from `vtkFlyingEdges3D`. `smooth_isocontour` smooths it with `vtkWindowedSincPolyDataFilter`, and `slice_isocontour` cuts the result along the centerline and returns `ContourSlice` objects holding ordered points from a closed Kochanek spline. Keep these points when changing this code:

- `sitk.SignedMaurerDistanceMap` alone is zero on boundary voxel centers, half a voxel inside the label. `signed_distance_field` averages it with the inverted mask's map so zero lies on the voxel edges.
- `signed_distance_field` then smooths with a recursive Gaussian to remove the voxel staircase. The default sigma, per axis, puts 3 voxel edges in the central 95%. It rounds sharp edges, costing the test fixture about 5% of its volume. Pass `sigma=0` for the exact field.
- `extract_isocontour` pads the field so the mesh stays closed where a label touches the image edge.
- `smooth_isocontour` turns boundary and feature-edge smoothing off and non-manifold smoothing on, and normalizes coordinates so its parameters don't depend on physical scale. The Gaussian leaves ripples in the mesh that make slice contours wiggle. The defaults, 50 iterations at pass band 0.001, cut the contours' excess turning by about 70% on the real test label and cost about 3% of the volume. A pass band of 0.001 at 100 iterations shrinks the fixture by 11%. `iterations=0` disables smoothing.
- A cutting plane is infinite and can also cut the far limb of the C-shaped structure, so each slice takes the loop nearest the centerline.
- Contours run counterclockwise about the slice normal. Each one's point order is rotated to match the previous slice, because a loft joins contours by parameter and a drifting start point makes the surface bulge at sharp corners.
- Slices are clipped only from the two ends, until one reaches 20% of the mean area. A narrow section between the ends is kept.

### B-reps through gmsh

gmsh holds its models in global state, so a `BRep` is a plain value holding the `.brep` file's text, and all gmsh work happens inside `gmsh_session()`. Keep these points when changing `geo.meniscus.contours_to_brep`:

- gmsh treats a B-spline whose first and last point tags match as periodic, so contours are built with periodic knots.
- The loft does not use `addThruSections`. Open Cascade's approximation overshoots in the end spans where real sections taper toward the horns, folding the surface, and gmsh's 2D meshing then never finishes; C1 continuity, every `parametrization`, and shared contour knots did not prevent it on the real lateral meniscus after label Gaussian assembly. Instead `brep.add_periodic_swept_surface` interpolates periodic contour splines that share one knot vector (fitted at the mean of the contours' chord parameters), with each column of poles interpolated along the curve at slice-center chord parameters, as for the hexahedral blocks. The surface then passes exactly through every contour, and its end rims are the end contours' curves.
- Solids are built from the lofted surface, the two caps, and a sewn surface loop.
- A smooth cap reuses the end contour's poles and knots so its rim matches the loft's edge. Its quadratic meridians collapse to one apex by repeating the apex point tag for the last row of poles.
- Planar caps need contours projected exactly onto their planes, because VTK's single-precision points fall outside Open Cascade's tolerance.
- The loft's degree along the curve is `min(spline_order, 3, slices - 1)`, so `spline_order=1` gives a single ruled (1, 1) face.
- `gmsh.write` exports only the highest-dimension shapes, so stray wires do not need removing.
- `occ.getMass` is unreliable on ruled surfaces (`spline_order=1`). Mesh the shape to check its volume.

### Hexahedral blocks

`contours_to_hex_blocks` splits each section with a butterfly (O-grid) partition: an inner quadrilateral block plus four outer blocks, one on each of four boundary arcs, joined by straight spokes. Every boundary point meets an inward spoke, so boundary cells stay near square even at the meniscus's sharp, smoothing-rounded corners. The Y split it replaced put block corners at those corners, which gave cells nearly 180° angles there and inverted elements on the real test label. Keep these points when changing it:

- The four splits divide the contour into equal-length arcs. `_butterfly_split_indices` rotates them to minimize the turning angle near them, averaged over all slices, so corners fall mid-arc. The first split is a point index because each contour is rolled to start there.
- Inner block corners lie halfway (`_INNER_BLOCK_SCALE`) from the section centroid to the split points. Mesh quality barely changes between 0.35 and 0.7.
- Each arc is sampled at `_PIECE_SAMPLES` points for its face's section curves. Fewer than 20 move the faces more than 1e-3 off the contour points.
- It does not use `addThruSections`. Separate lofts choose their own parameterization along the curve, so adjacent lofts cross between slices and fragment shatters them. Instead every face is a B-spline surface interpolating section curves fitted with a shared knot vector, with each column of poles interpolated along the curve at shared parameters. A face's edges then depend only on their own points, so neighboring faces match exactly.
- Each block is sewn separately, then the blocks are fragmented, which merges the identical copies of shared spoke faces. Trimming faces with existing curves (`wireTags`) does not share edges, because gmsh projects new ones.
- `hexahedral_mesh` makes every curve, surface, and volume transfinite. Curves on the planar caps get `elements_per_edge` and all others `elements_along`.
- Hexahedral tests use 10-point contours, which give valid elements and small B-reps. Contours need at least 8 points.
- gmsh's "initial mesh only" 2D algorithm crashes the process with a segmentation fault, and BAMG fails on these shapes, so `Algorithm2D` omits them. `Algorithm3D` omits R-tree, which writes `new_points.pos` into the working directory.

### Hexahedral mesh optimization

`optimize_hexahedral_mesh` runs smart Laplacian smoothing, then projected gradient descent on the sum of 1 / SJ over all element corners plus `aspect_weight` times the sum of their squared Frobenius aspect ratios. Keep these points when changing it:

- The objective is infinite for any corner with a determinant at or below zero, so a backtracking step can never invert an element. Optimization therefore needs a valid start: if smoothing leaves an element inverted, `_untangle` first minimizes the sum of max(0, 0.2 - SJ)^2 over all corners, whose gradient dSJ/de_k = cof_k / prod |e_k| - SJ e_k / |e_k|^2 is finite through det E = 0, stopping as soon as none is inverted, and optimization is skipped with a warning only if one still is. The femoral cartilage's sized blocks have a column of inverted elements beside block vertices whose corner in the domain is nearly 180 degrees, 4 at 2 mm and 13 at 1 mm, which smart Laplacian leaves; untangling takes 3-4 steps there.
- 1 / SJ, unlike Knupp's condition number, does not penalize unequal edge lengths, so it leaves the deliberately long elements along the meniscus alone. It weighs the worst corners most. Alone it squares corners up by stretching elements: it raised the real medial meniscus's largest Frobenius aspect ratio from 24 to 89 and the medial tibial cartilage's from about 20 to 42, or to 11 with its walls kept straight.
- The Frobenius aspect ratio of a corner is F = |E|_F^2 / (3 det(E)^(2/3)), Verdict's maximum aspect Frobenius over the eight corners for an element (`frobenius_aspects`, and `max_aspect` and `mean_aspect` in `MeshQuality`). It is 1 for a cube and also a barrier as det E falls to 0. Its gradient is d log F / dE = 2E / |E|_F^2 - (2/3) E^-T, reusing the cofactors. Squaring it weighs the worst corners more; F^2 lowered the real cartilage's largest aspect ratio about 10% more than F. `aspect_weight` defaults to 0 in `StructureMesh` and the function, so the meniscus keeps 1 / SJ alone: at 0.5 its mean scaled Jacobian fell from 0.80 to 0.68, fighting its deliberately long elements. `CartilageMesh` defaults to 0.5; between 0.5 and 2 the results barely differ.
- The gradient uses d log SJ / dE = E^-T - e_k / |e_k|^2 for the matrix E of a corner's edge rows, with E^-T from cross products rather than `np.linalg.inv`, and scatters with `np.bincount`; `np.add.at` and batched `inv` made it twice as slow. Steps are scaled by each node's local size squared so the step length is dimensionless.
- Boundary nodes are classified from the mesh's own boundary quadrilaterals, not the B-rep: feature edges are where adjacent boundary faces meet at more than `feature_angle`; nodes where feature edges end, branch, or turn are fixed. Surface nodes are limited to `surface_deviation` off and `surface_travel` along their starting tangent plane, as fractions of the mean incident edge length; feature edge nodes the reverse.
- A `Mesh`'s `straight_lines` are chains of nodes whose inner nodes stay at their starting fractions along the segment between the chain's ends (`_LINE` nodes), which move as their own kind allows; `line_gradient` passes the inner nodes' gradient to the ends, and smart Laplacian undoes a line's ends when it undoes its inner nodes. The sheet mesher fills it with each rim node's column, which lies on the wall. Without it, wall columns bowed by 13-17% of the thickness on average after optimization, up to 38%, which was most of the scaled Jacobian alone's stretching; with it the cartilage's results barely change.
- Optimization pushes surface nodes outward: at `surface_deviation` 0.1 the real menisci swell 5-7%. `preserve_volume` removes the area-weighted mean normal offset in the projection, which keeps volume within 0.5% at the same quality.
- Smart Laplacian is a Jacobi sweep that undoes moves around any element that got worse, repeating until none did. It untangles the inverted test grid but barely changes gmsh's transfinite meshes; the optimization does most of the work there.
- High-order nodes move by trilinear interpolation of their element's corner displacements, using the local node coordinates gmsh reports, so curved edges keep their offsets. Quality is measured on corners only.
- On the real menisci at 4 by 20 elements, 1 / SJ optimization takes about 2 s and raises the minimum scaled Jacobian from 0.08-0.17 to 0.36-0.40 and the mean from 0.64-0.72 to 0.80-0.83. 1000 steps instead of 200 add little.

### Cartilage sheets

The lateral and medial tibial and the patellar cartilage are sheets: `classify_sides` splits the smoothed surface into its two sides, `fit_sheet` fits them as heights over the plane normal to the sides' thinnest principal direction, and `sheet_to_brep` builds the solid. On the real labels, under 1% of the side points face against that normal, all near the rim, so heights over one plane suffice. The femoral cartilage wraps the condyles and is not a height field over any plane; it uses the same code over a cylinder (see Femoral cartilage). Keep these points when changing this code:

- `classify_sides` compares each outward normal (`vtkPolyDataNormals` with `AutoOrientNormals` on the largest connected region) with the bone distance field's gradient, not with an axis, so it also works for the femoral cartilage. On the real labels the cosines are sharply bimodal. `DEFAULT_SIDE_COSINE` is 0.3: hexahedra stay valid there, and it keeps about 2% more volume than 0.5.
- The wall at the perimeter is straight, ruled between the two sides' edges, and tilted: `CartilageSheet.tilt` is how far the articular edge lies outward of the bone edge in the domain, and `tilted` moves each side's domain points half of it along the perimeter's outward normal, fading as the square of the distance out to `perimeter_radius` inside. Outside, the square of the signed distance continues, up to four times the move at `perimeter_radius`, so the sides' surfaces, which reach past the perimeter to be trimmed, have no crease along it; fading by unsigned distance gave the move's slope opposite signs on either side of the perimeter. `_wall_tilt` sets it to the mean over both sides of -h g (thickness times the outward slope), which balances the wall's angles to the two sides, limited to 0.25 of the local thickness and of `perimeter_radius` and smoothed along the perimeter by a Gaussian of half the radius, limited again. Along the normal, the articular side curves down at the rim, so the angles inside the sheet were 117-135 degrees at the median on the articular side and 92-103 on the bone side. With the butterfly blocks this replaced, after optimization the tilt brought the largest deviation from 90 degrees from 34-49 to 24-36 degrees, at a cost of up to 13% in the largest aspect ratio (the medial tibial cartilage's, 5.8 to 6.5). Moving the articular side out as far as its points reach and the bone side in for the rest, instead of half each, raised aspect ratios more; with it, a cap of 0.35 left the medial tibial cartilage's at 37 and 0.5 inverted it.
- Each side's footprint is the pixels within a closing distance of its points (4 median point spacings), shrunk back by that distance, so gaps narrower than that close. The sheet covers where both footprints overlap, so the steep rim between the sides is cut off. Regions inside the overlap's filled outline that neither side covers are defects.
- The perimeter is the overlap, moved `perimeter_inset` inward, closed and then opened by a disk of radius `perimeter_radius` from exact distance maps, and smoothed by a Gaussian of half that radius. Rolling the disk bounds the radius of curvature, concave and convex; the Gaussian alone left the real lateral tibial cartilage's notch tighter than one hexahedron, which inverted elements across it. The final Gaussian loosens the bound by under 15%. The defaults are 3 mm for hexahedra and 1 mm for tetrahedra. Rounding costs 1-3% of the overlap's area. A 2 mm convex radius with a 3 mm concave one kept 2% more of the real lateral tibial cartilage, at a spur, but lowered its optimized minimum scaled Jacobian from 0.56 to 0.31, and the others barely gained. With the butterfly blocks this replaced, at their default counts, the real lateral tibial cartilage's minimum scaled Jacobian was -0.02 at 2 mm, 0.24 at 2.5 mm, and 0.35 at 3 mm; with the extruded quadrilaterals at 2 mm, sheets with the 1 mm tetrahedral perimeter optimize to similar minimum scaled Jacobians (0.44-0.70) but larger aspect ratios (3.0-5.8 against 2.6-3.5), so the hexahedral defaults keep 3 mm.
- Heights are linear interpolation (`griddata`) on a grid of half the point spacing, nearest beyond the points, smoothed by a 2-pixel Gaussian and fitted with `RectBivariateSpline`. The perimeter lies inside both sides' points, so heights inside it are interpolated, not extrapolated.
- Thickening lowers the bone side to the articular height minus a smooth maximum of the thickness and the minimum, `(h + m + sqrt((h - m)^2 + b^2)) / 2` with `b` half the minimum. It is at least the minimum everywhere and leaves the articular side untouched. Thickened cartilage may overlap its bone; bone processing will run downstream and adjust the bone, never the cartilage.
- For hexahedra the pipeline passes `hole_thickness` 0, so their B-reps have no holes, though `mesh.sheet.hexahedral_mesh` meshes around any (on the synthetic defect one element beside the hole starts barely inverted, and optimization untangles it). For tetrahedra, connected regions thinner than `hole_thickness` of the mean, or defects, become holes when their rounded outlines lie `perimeter_radius` inside the perimeter. Rounding makes holes narrower than the radius vanish. `sheet_to_brep` trims both sides by each hole's outline and rules a wall between them, along the height lines, since the tilt has faded there.
- Volume: on the real labels the B-reps hold 92-96% of the voxel volume at either element shape's defaults. The distance-field Gaussian and windowed sinc smoothing cost 3-6%, and cutting off the rim the rest. None of the real labels gets holes at the defaults.

### Sheet solids and hexahedra

`sheet_to_brep` builds one solid for both element shapes, and `mesh.sheet.hexahedral_mesh` partitions it while meshing. They replaced a butterfly of five blocks (seventeen for the femoral cartilage) built into the B-rep, whose structured blocks tied each edge count to every edge opposite it, so sizes varied up to fivefold within a class and smaller femoral sizes left elements inverted beside block corners that were nearly 180 degrees. Keep these points when changing this code:

- Each side interpolates its tilted points on a grid of `_SURFACE_SPACING` (0.5 mm) reaching three spacings past the perimeter: one `RectBivariateSpline` per coordinate, whose knots and coefficients become the poles of one B-spline surface, so its parameters are (s, t). It is trimmed by the perimeter and holes drawn in parameter space (`wire3D=False`), so both sides share bounds and parameterization. Interpolating at 0.5 mm stays within 0.02-0.07 mm of the sheet's points; 1 mm gave 0.10-0.19, and least squares at the same pole count was no better. The B-reps are 1.6-2.6 MB, and 10 MB for the femoral cartilage, and build in under 1 s.
- Walls are lofted (`addThruSections`, ruled) between the sides' rims, matched by loop (`_rims_by_loop`), so they share edges with the sides and sew without booleans. The loft pairs the rims by their own parameters, which match equal (s, t) within 1e-5 mm on the tibial and patellar sheets but only within 0.13 mm on the femoral, so the mesher follows the wall's rulings rather than pairing equal parameters at the rims. Rejected: a wall through both sides' points at equal parameters as a periodic swept surface. Its rims lie within 2.7e-4 mm of the trimmed edges, but sewing never merged them at any tolerance, `healShapes` made no solid, and fuzzy fragmenting at 1e-3 merged them on the tibial sheets but shattered the femoral bone rim into 374 curves and 21 slivers.
- `occ.getMass` is unreliable with the ruled walls; measure volumes from tetrahedra. Tetrahedral volumes of these solids are within 0.6% of the partitioned solids'.
- `hexahedral_mesh` takes the two largest faces as the sides (`_sheet_sides`, which checks that walls join them) and meshes only the larger, with `Mesh.MeshOnlyVisible`, in its own 3D metric. Interior nodes pair with the other side at their parametric coordinates from `getNodes(..., returnParametricCoord=True)`; rim nodes map their curve parameters onto the wall with `reparametrizeOnSurface`, and their columns end at the other end of the wall's ruling. Projecting with `getParametrization` and `getClosestPoint` instead took 10 s for 1500 nodes. Layers divide the columns evenly. Second-order hexahedra come from a second-order quadrilateral mesh, matching each hexahedron node to the quadrilateral node at its reference (u, v) and the layer at its w; the layers are reversed if the meshed side is the upper one.
- Quadrilaterals only: Frontal-Delaunay for quads (`Mesh.Algorithm` 8) with simple full-quad recombination (2) left two triangles in 2 of 368 meshes of the real sheets at sizes 0.75-3.5 mm. The boundary's edge count was even, and `RecombineMinimumQuality`, `RecombineOptimizeTopology`, and `RecombineNodeRepositioning` changed nothing; sizes 4% off fixed both. So the size is changed by 2, 4, then 6% each way, and as a last resort a blossom-recombined mesh at twice the size is subdivided (`Mesh.SubdivisionAlgorithm` 1), which always gives quadrilaterals but optimized to minimum scaled Jacobians of 0.20-0.48 against 0.36-0.69. Blossom full-quad recombination (3) also left triangles, and much poorer quadrilaterals.
- `quasi_structured` is gmsh's algorithm 11, which aligns a cross field (4-RoSy) with the boundary, places its singularities, and leaves few irregular nodes: 4 on the real lateral tibial cartilage at 2 mm and 8 on the femoral, against 25 and 130 for Frontal-Delaunay. It recombines on its own (recombination 0; full-quad would subdivide its mesh again). Its conformal scaling shrinks elements: edges of 0.6-1.8 mm at 2 mm on the real patellar cartilage and about 0.75 of the size elsewhere, under every `Mesh.QuadqsSizemapMethod`, while Frontal-Delaunay's span about 0.65-1.15 of the size. It takes 5 s on the femoral cartilage at 2 mm and 35-47 s at 1 mm. So Frontal-Delaunay is the default.
- On the real cartilage at 2 mm, 3 through, with `aspect_weight` 0.5, Frontal-Delaunay hexahedra optimize to minimum scaled Jacobians of 0.49-0.67, means of 0.92-0.94, and largest Frobenius aspect ratios of 2.6-3.5, from minima of 0.15-0.56 before; quasi-structured ones to 0.47-0.67, means of 0.94-0.97, and 2.3-3.1. The butterfly blocks reached 0.53-0.64 and 3.1-6.5. At 1 mm Frontal-Delaunay gives 0.45-0.72 and 1.9-2.7, the femoral cartilage 0.55-0.58 with none inverted. The scaled Jacobian alone raises the minima further, to 0.68-0.76 on the medial tibial and femoral cartilage, but stretches elements, to an aspect ratio of 8 on the patellar against 2.3.
- `sheet_partition_brep` builds the base complex of the side's quadrilaterals (`_base_complex`): separatrices leave each irregular node, an interior node with other than four edges or a rim node with other than three, and run straight through regular interior nodes until a rim or another irregular node; the quadrilaterals they enclose form patches, each a regular grid (`_patch_grid`), conforming with its neighbors. Each patch becomes a block of B-spline patches through its columns' ends and ruled walls, fragmented with the fuzzy tolerances `_FRAGMENT_TOLERANCES` (1e-3, 3e-2, then 1e-1 of the thickness) that the butterfly blocks needed. Grids are transposed to a right-handed frame first (`_right_handed`): Open Cascade made the other handedness a volume of negative size, and fragmenting then left a block with 28 faces. Quasi-structured quadrilaterals at 2 mm give 10 blocks on the real lateral tibial cartilage in 6 s and 32 on the femoral in 32 s.

### Femoral cartilage

The femoral cartilage is a sheet over a `CylinderFrame`: s along the axis, t arc length at the sides' mean radius, heights distances from the axis, and walls along rays from it away from the perimeter, tilted at it as for the other sheets. On the real label the sides span about 210 degrees around the axis, and unrolled they form a U: the trochlea joining two condylar legs around the notch. Its solid and hexahedra are made as for the other sheets. Keep these points when changing this code:

- `CylinderFrame.fit` takes the axis as the direction the bone side's normals (local PCA of 16 neighbors) vary least along, and its position from a circle fitted to the bone side projected along it. On the real label the rays leave the bone's normal by 25 degrees at the median and 41 at the 90th percentile, mostly medial-laterally (the trochlear facets and the condyles' sides), which no choice of axis removes; the sagittal part is 5-19 degrees at the median.
- Each side's surface spans the U's bounding rectangle, notch included, and is trimmed to the U.
- On the real label at 2 mm, 3 through (about 3900 hexahedra), the minimum scaled Jacobian is 0.30-0.45 before optimization and 0.50-0.60 after, mean 0.93, and the largest Frobenius aspect ratio 5.1-5.4 before and 3.25-3.33 after; the range spans label Gaussian and nearest-neighbor assembly.
- Tetrahedra default `max_size` to `element_size`: the oriented bounding box default, about 30 mm across, gave a minimum volume ratio of 0.005, against 0.04 (mean 0.74) at 2.5 mm. The tetrahedral solid holds about 94% of the voxel volume.

### Bones

The femur, tibia, and patella are surfaces gmsh reparametrizes, not B-reps: a true B-rep of a closed, freeform bone would need a patch layout. Keep these points when changing this code:

- `find_shaft_ends` calls an end cut off by the scan where the label's last slice along an image axis holds over 5% of its largest slice and over 60% of the slice 2 mm inward. The real femur's and tibia's cuts hold 15-22% and 80-83%; natural ends and sides at most 5% and 34%. The fraction alone also caught a synthetic cylinder's sides (29%) and its rounded end's tip (8%).
- `bone_mask` cuts in the voxel map, so smoothing rounds the cut's edge. It fills cavities, first in a cut's new last slice, where a pocket would open onto the flat face (the real tibia has one), then in 3D.
- Bones smooth with non-manifold smoothing off (`smooth_isocontour(..., non_manifold_smoothing=False)`); the other structures keep it on.
- `decimate_surface` targets triangles of `triangle_size` by area. The real femur's 340,000 isocontour triangles took gmsh minutes to reparametrize; at 1 mm the surface moves at most 0.02 mm and reparametrizes in under 1 s. A rejected design clipped the surface at the cut and capped it with a flat triangulation: decimating the cap's slivers flipped triangles, and decimating first left a zigzag loop, both splitting gmsh's patches.
- `_reparametrize` classifies with angle pi, splitting only where gmsh needs to map patches to a plane: at 40 degrees, single sliver triangles that decimation folded by 44-54 degrees became patches of their own and near-degenerate elements.
- Quadrilaterals use `mesh.sheet.quadrangulate` with Frontal-Delaunay. Its full-quad recombination subdivides, and on discrete surfaces gmsh leaves the new nodes up to 1 mm off the surface; second-order nodes placed through the parametrizations land up to half an edge off at patch seams. So middle nodes are made straight (`Mesh.SecondOrderLinear`) and every node is projected onto the input surface (`_project_nodes`). Projecting onto each patch's own triangles followed the seams' zigzag, up to 0.46 mm off, and gmsh's `getClosestPoint` on patches collapsed elements. The quasi-structured algorithm took 50 s on the real patella and made elements a third of the size, so it is not offered.
- `_smooth` runs 10 Laplacian sweeps over the whole surface, projecting onto it, before any volume or high-order nodes: gmsh's Laplace2D keeps nodes on patch seams, which left a quadrilateral of scaled Jacobian 0.04 on the real femur. It raised the real bones' smallest quadrilateral corner scaled Jacobian to 0.57-0.74 and triangle quality to 0.69-0.78. A gmsh compound (`mesh.setCompound`) cannot replace it: a compound must map to a disk, and the bone's closed surface, two patches at angle pi, has no boundary, so a compound of every patch fails with "Invalid exterior boundary mesh for parametrization" or, with `Mesh.CompoundClassify` 0, crashes the process, and compounding only the seam curves lowered the real patella's smallest quadrilateral corner to 0.
- Tetrahedra are sized by a gmsh size callback from the distance to the surface's vertices (a `KDTree`): `cortical_element_size` within `cortical_distance`, growing by `cancellous_grad` per unit of depth to `max_size`. `Mesh.MeshSizeExtendFromBoundary` is off so the field governs the interior. Netgen optimization (`Mesh.OptimizeNetgen`) removes the slivers the grading leaves: on the real femur the smallest volume ratio rose from 0.01 to 0.29, the mean from 0.74 to 0.83. Mean edges come out about 1.3 times the requested size near the surface, and Delaunay's coarsest interior edges average up to 5.2 at `max_size` 4. The real femur takes about 30 s at the defaults, mostly in the Python callback.

## Tests

Test files mirror the package: root modules have `tests/test_<module>.py`, and structure modules have `tests/geo/test_<structure>.py` and `tests/mesh/test_<structure>.py`. Duplicate basenames work because pytest runs with `--import-mode=importlib`. `tests/conftest.py` defines session-scoped fixtures that every test shares, so tests must not modify them in place:

- `meniscus_label` is a synthetic meniscus: a triangular cross-section swept 270° about the z axis, with the gap facing -x.
- `meniscus_centerline` is `centerline(meniscus_label)`. Use it instead of calling `centerline` on the same image again.
- `meniscus_distance_field`, `meniscus_mesh`, `meniscus_smoothed_mesh`, `meniscus_slices`, `meniscus_contours`, `meniscus_surface`, `meniscus_solid`, `meniscus_domed_solid`, `meniscus_hex_slices`, `meniscus_hex_blocks`, `meniscus_tetrahedra`, and `meniscus_hexahedra` are the later pipeline stages for the same label.
- `real_label` is the real lateral meniscus in `tests/dat/lateral_meniscus.nii`, and `real_medial_label` the medial meniscus of the same knee in `tests/dat/medial_meniscus.nii`. `tests/dat` is stored in Git LFS.
- `cartilage_segmentation` is a synthetic tibial cartilage (label 2) on a spherical tibia (label 1) of radius 40 mm whose top touches z = 0: an ellipse of semi-axes 15 and 10 mm, 3 mm thick at its center and tapering to its rim, with a Gaussian dip at x = -6 mm thinned to about 15% of the mean once fitted. `cartilage_defect_segmentation` adds a full-thickness defect of radius 2.5 mm at x = 6 mm. `cartilage_sides`, `cartilage_defect_sides`, `cartilage_sheet` (hexahedral defaults), `cartilage_hex_solid`, `cartilage_hexahedra` (2 mm), and `cartilage_solid` (tetrahedral defaults) are later stages. The bone side lies about 0.35 mm outside the analytic sphere, from voxelization.
- `femoral_segmentation` is a synthetic femoral cartilage (label 2), a 2 mm shell on a cylindrical femur (label 1) of radius 20 mm along x: a 68-degree trochlea across |x| <= 18 mm and 136-degree condyles at 6 <= |x| <= 18 mm. `femoral_sides`, `femoral_sheet`, `femoral_hex_solid`, `femoral_hexahedra`, and `femoral_solid` are later stages. Tests repeat its constants, since `--import-mode=importlib` cannot import conftest.
- `real_femoral_sides`, `real_femoral_sheet`, and `real_femoral_hex_solid` are the real femoral cartilage's stages, assembled with the femur by nearest neighbor.
- `bone_label` is a synthetic bone (label 1): a shaft of radius 6 mm along x from the image's edge at x = 0, 25 mm long to a hemispherical end, with a spherical cavity of radius 2 mm. `bone_surface` is its surface as the pipeline makes it (`bone_surface_of`), and `real_patella_surface` the real patella's.
- `real_cartilage` holds the `CartilageSides` of each real tibial and patellar cartilage, assembled with its bone by nearest neighbor, and `real_cartilage_hex_solids` their solids at the hexahedral defaults. Classifying the three sides takes several seconds, so share these instead of building again.

Every file in `tests/dat` is one structure of the same knee, named for its structure key: the two menisci plus `femoral_cartilage.nii`, `lateral_tibial_cartilage.nii`, `medial_tibial_cartilage.nii`, `patellar_cartilage.nii`, `femur.nii`, `tibia.nii`, and `patella.nii`; every file is read by some test. Each is a single label 1 in `sitkUInt8`, cropped to the label's bounding box (`sitk.LabelShapeStatisticsImageFilter`, with no margin). The grids share spacing and orientation and are offset by whole voxels, so nearest-neighbor assembly reproduces every label exactly. SimpleITK has no 1-bit pixel type and ITK does not write NIfTI's binary type, so `sitkUInt8` is the smallest.

The fixture's voxelized cross-section centroid is r = 16.43, z = -1.67, not the ideal triangle's r = 16.67, z = -1.33. Its bottom slice lies exactly on the triangle's base and counts as a whole voxel layer, which also makes its voxel volume about 12% above the analytic value. Compare against the voxelized values or use a suitable tolerance.
